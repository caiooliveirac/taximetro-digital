## Commit 9fda8d1: Filtro de Arquivados + Candidatos a Arquivamento

**Data**: 2026-04-20 06:17:51 UTC

**Problema resolvido:**
- Interns arquivados continuavam aparecendo na seção de "pendências" do dashboard de liderança
- Não havia forma visual de identificar interns que deveriam ser arquivados por inatividade (21+ dias)

**Mudanças em [src/app/leader/page.tsx](../src/app/leader/page.tsx)**:

### 1. Estado para rastreamento de internos arquivados
```typescript
const [archivedInternIds, setArchivedInternIds] = useState<Set<string>>(new Set());
```
- Mantém em memória lista de IDs de internos arquivados
- Usado para filtrar antes de renderizar

### 2. Carregamento de status de arquivo
```typescript
useEffect(() => {
  // ... em load data
  if (usersJson.success) {
    const archived = new Set<string>(
      usersJson.data
        .filter((u) => u.role === "INTERN" && u.isActive && u.isArchived)
        .map((u) => u.id)
    );
    setArchivedInternIds(archived);
  }
}, [/* deps */]);
```
- Consulta lista de usuários (/api/admin/users)
- Filtra INTERN + isActive + isArchived
- Popula Set para O(1) lookup

### 3. Filtro em pendências
```typescript
const filteredPendingAttendance = pendingAttendance.filter((assignment) => {
  // ... outros filtros
  if (archivedInternIds.has(assignment.internId)) return false; // ← NOVO
  return true;
});
```
- Remove assignments de internos arquivados
- Evita false positives no dashboard

### 4. Seção "Sem atividade nos últimos 21 dias"
```typescript
const twentyOneDaysAgo = addDaysToDateStr(today, -21);
const archiveCandidates = compliance.filter((row) => {
  const internAssignments = monitorAssignmentsByIntern.get(row.userId) ?? [];
  return !internAssignments.some((a) => a.date >= twentyOneDaysAgo);

```
- Calcula quais internos não tiveram plantão nos últimos 21 dias
- Usa data operacional (não simples hoje)
- Mostra lista com data do último plantão

**Impacto:**
- Pendências agora 100% corretas (arquivados excluídos)
- Visibilidade de interns a arquivar

## Commit 722bfe5: Arquivamento em Lote + Exibição de Última Atividade

**Data**: 2026-04-20 06:25:07 UTC

**Problema resolvido:**
- Leitor precisava arquivar um-por-um cada intern inativo
- Não era visível quando foi o último plantão

**Mudanças em [src/app/leader/page.tsx](../src/app/leader/page.tsx)**:

### 1. Estado para gerenciar arquivamento em lote
```typescript
const [archivingAll, setArchivingAll] = useState(false);
```
- Flag para desabilitar botões durante requisição

### 2. Função de arquivamento em lote
```typescript
async function handleArchiveAllCandidates(candidates: ComplianceRow[]) {
  setArchivingAll(true);
  try {
    const results = await Promise.all(
      candidates.map((c) =>
        fetch("/taximetro/api/admin/users", {
          method: "PUT",
          headers: { "Content-Type": "application/json" },
          body: JSON.stringify({ id: c.userId, isArchived: true }),
        })
      )
    );
    
    const allSuccess = results.every((r) => r.ok);
    if (allSuccess) {
      setArchiveMsg("✅ Todos os candidatos foram arquivados");
      await load(); // Recarrega dados
    } else {
      setArchiveMsg("⚠️ Alguns arquivamentos falharam");
    }
  } finally {
    setArchivingAll(false);
  }
}
```
- Arquiva múltiplos internos em paralelo (Promise.all)
- Valida que todos os requests tiveram sucesso
- Recarrega dados automaticamente
- UX: timeout de 1.5s antes de limpar mensagem

### 3. Exibição de última atividade
```typescript
const lastDate = internAssignments
  .filter((a) => a.date < today)
  .sort((a, b) => b.date.localeCompare(a.date))[0]?.date;

return (
  <div className="flex items-center justify-between">
    <span>{c.name}</span>
    <span className="text-xs text-slate-400">
      {lastDate ? `último: ${shortDate(lastDate)}` : "sem plantão registrado"}
    </span>
  </div>
);
```
- Encontra plantão mais recente (anterior a hoje)
- Usa `shortDate()` para formato DD/MM
- Fallback para "sem plantão registrado"

### 4. Botões de ação
```typescript
{/* Botão em lote */}
<button
  onClick={() => handleArchiveAllCandidates(archiveCandidates)}
  disabled={archivingAll || archiveCandidates.length === 0}
  className="px-3 py-1.5 bg-amber-100 text-amber-900 rounded text-sm hover:bg-amber-200"
>
  Arquivar todos ({archiveCandidates.length})
</button>

{/* Botão individual */}
<button
  onClick={() => handleArchiveIntern(c.userId)}
  disabled={archiving || archivingAll}
  className="px-2 py-1 bg-slate-200 text-slate-700 rounded text-xs hover:bg-slate-300"
>
  Arquivar
</button>
```
- Botão "Arquivar todos" em amber (destaque, mas não crítico)
- Botão individual em cada linha
- Estados sincronizados (desabilitados durante requisição)

**Impacto:**
- Arquivamento de 10-20 interns inativos em 1 clique vs 10-20 cliques
- Lider vê imediatamente quando foi a última atividade
- UX mais intuitivo

## Commit b9c5974: Restrição de Papéis em Scheduling

**Data**: 2026-04-20 06:33:17 UTC

**Problema resolvido:**
- Líderes com papel LEADER-only estavam aparecendo no sorteio e alocação manual
- Líderes que deveriam ser escaláveis (ex: UNIFACS) eram difíceis de alocar

**Mudanças em 5 arquivos de repositório**:

### Arquivo 1: src/features/user-management/infra/repositories/user-management-repository.ts

**Função**: `listFacultyInternRows(facultyId)`

Antes:
```typescript
inArray(userRoles.role, ["INTERN", "LEADER"])
```

Depois:
```typescript

```

**Impacto**: Endpoint `/api/leader/interns` agora retorna apenas usuários com papel INTERN (não LEADER-only)

**Função**: `getValidInternIdsForFaculty(params)`

Antes:
```typescript
inArray(userRoles.role, ["INTERN", "LEADER"])
```

Depois:
```typescript

```

**Impacto**: Sorteio (lottery) agora aceita apenas INTERN, filtrando LEADER-only automaticamente

### Arquivo 3: src/features/scheduling/infra/repositories/cru-fixed-repository.ts

**Função**: `internBelongsToFaculty(params)`

Antes:
```typescript
inArray(userRoles.role, ["INTERN", "LEADER"])
```

Depois:
```typescript
eq(userRoles.role, "INTERN")
```

**Impacto**: Validação de bloqueio CRU fixo agora funciona apenas para INTERN

### Arquivo 4 & 5: src/features/requests/infra/repositories/request-repository.ts

**Funções**:
- `findFacultyInternIds(facultyId)`
- `findRequesterFacultyRole(requesterId)`
